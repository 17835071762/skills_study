# Skills 触发机制详解

## 触发机制的基本原理

### 技能调用的决策权归属

技能并非由用户直接进行调用操作，而是由Claude根据任务需求自行判断是否启用某个技能。理解这一决策过程的工作原理，能够帮助你编写出更容易被准确触发的技能配置。

### 触发机制的运行流程

当Claude启动运行时，系统会将所有可用技能的名称和描述信息加载到其上下文中。在接收到用户发送的消息后，Claude会进行判断：当前处理的任务是否需要参考某个技能中的专门指令？

这个判断过程所依据的唯一标准是技能描述字段的内容。技能文件正文部分的信息并不会参与到触发判断环节中。只有当Claude做出决定要使用某个技能之后，系统才会开始读取该技能文件的正文内容。

触发过程的整体流程如下：
- 系统启动时加载所有技能的name和description
- 用户发送任务请求
- Claude依据description判断是否需要技能辅助
- 如果判断为需要，则读取对应技能的SKILL.md正文
- 如果判断为不需要，则直接处理用户请求

## 任务类型与触发条件的关系

### 触发技能的任务特征

并非所有与技能描述相匹配的请求都会触发技能使用。Claude内部存在一个判断逻辑：当前任务的复杂程度是否需要参考专门的操作指令。

不同任务类型与触发倾向的对应关系如下：

**简单单步任务**：例如"读取这个PDF文件"，通常不会触发技能。因为Claude直接处理这类任务反而更加高效。

**复杂多步任务**：例如"提取PDF文件中的表格数据并转换为Excel格式"，这类任务会触发技能。原因在于任务涉及多个步骤，需要遵循专门的工作流程。

**专业领域操作**：例如"合并三个PDF文件并添加水印"，这类任务会触发技能。因为操作过程中需要使用特定的工具链。

**输出格式要求明确的任务**：例如"生成一份符合我们公司模板标准的Word报告"，这类任务会触发技能。因为输出结果需要符合特定的格式规范。

### 触发率低的常见原因

如果你的技能很少被触发，通常是因为用户任务描述过于简单，或者技能的描述字段写得不够精准。在进行技能触发测试时，应该使用复杂且具体的用户请求。

## 技能描述字段的编写策略

### 策略一：列举具体应用场景

编写描述时，不应仅仅说明"这个技能能够做什么"，还要明确写出"在什么情况下应该使用它"。

**不推荐的写法示例**：
```
description: 处理Excel文件。
```

**推荐的写法示例**：
```
description: >
  处理Excel和CSV文件，包括：读取数据、清洗格式、生成图表、
  计算统计指标、合并多个表格。当用户提到Excel、xlsx、CSV、
  表格数据、数据清洗、财务报表时，应优先使用此Skill。
```

### 策略二：使用推动性语言

技能系统本身具有倾向于"少触发"的特性。在描述字段中加入推动性语言可以有效提升触发概率。

**推荐写法示例**：
```
description: >
  生成专业的PowerPoint演示文稿。当用户需要制作幻灯片、PPT、演讲稿、
  汇报材料时，必须使用此Skill，即使用户没有明确说"用pptx格式"。
  只要涉及演示文稿的创建或修改，都应触发此Skill。
```

### 策略三：列出关键词

在描述字段末尾附上触发关键词列表，是一种简单有效的补充手段。

**推荐写法示例**：
```
description: >
  代码审查助手，分析代码质量、发现潜在Bug、给出改进建议。
  关键词：code review、代码审查、代码分析、bug检查、
  重构建议、代码质量、静态分析。
```

## 多技能触发冲突处理

### 冲突的产生与识别

当用户请求可能同时匹配多个技能时，Claude会根据匹配程度选择最相关的一个技能。为了避免触发冲突，需要让不同技能的描述字段保持清晰的边界。

### 常见冲突场景的解决方案

**场景一：两个技能都处理PDF文件**
解决方案：在各自的描述字段中区分具体的操作类型，例如一个技能标明"PDF创建"，另一个技能标明"PDF读取"。

**场景二：通用技能与专用技能功能重叠**
解决方案：在专用技能的描述字段中明确写出区别于通用技能的应用场景。

**场景三：两个技能功能相似**
解决方案：考虑将两个技能合并为一个技能，通过内部的逻辑分支来处理不同的应用情况。

### 描述字段的排他性原则

技能的描述字段应当以"排他性"的方式来描述自己的适用场景，而不仅仅是描述自己"能够做什么"。能够做什么并不等于应该在什么时候被使用。

## 描述字段优化工具的使用

### 测试工具介绍

skill-creator技能提供了一个描述字段优化脚本，可以自动评估技能触发的准确率。

### 工具使用实例

运行描述字段优化循环的命令行示例如下：

```bash
# 运行description优化循环
# --eval-set：测试用例文件路径
# --skill-path：待优化的Skill路径
# --max-iterations：最大迭代次数
python -m scripts.run_loop \
  --eval-set evals/trigger-eval.json \
  --skill-path my-skill/ \
  --model claude-sonnet-4-20250514 \
  --max-iterations 5 \
  --verbose
```

该脚本会自动执行以下操作：运行测试用例、评估得分、修改描述字段内容，并最终输出最优化的结果。
