# Skills 技术指南

## 一、Skills 基础认知

### 1.1 什么是 Skills

Skills 采用开放格式设计，目的是为 AI 代理程序添加专门的技术能力和知识储备。通过这种格式，能够将特定领域的专业经验、操作流程以及行业最佳实践整合成可重复使用的功能包，当 AI 代理需要处理相关任务时，可以自动调用这些技能包。

### 1.2 AI 智能体的基本概念

在正式学习 Skills 之前，需要先理解一个更基础的问题：AI 智能体的定义是什么。

目前广泛使用的 ChatGPT、豆包、通义千问等工具，用户通过文字提问，它们返回文字答案，这类工具被称为大模型聊天机器人。这些聊天机器人虽然智能程度较高，但存在一个根本性局限：它们只能提供语言交互，无法执行实际操作。例如询问“今天北京天气怎么样”，这类工具只能依据训练阶段学习到的数据推测一个答案，而不是真正去查询实时天气数据。

AI 智能体的定义可以概括为：能够理解用户指令、进行自主思考并执行实际任务的 AI 助手。聊天机器人相当于“语言替代者”，而智能体则是真正的“行动替代者”。

从技术构成来看，智能体的公式为：智能体 = 大模型 + 实际执行任务的能力。通过具体例子对比两者的区别：

| 任务场景       | 聊天机器人的响应                       | 智能体的响应                                        |
| -------------- | -------------------------------------- | --------------------------------------------------- |
| 询问北京天气   | 推测回答“北京今天大概晴天，气温约25度” | 真实调用天气接口，返回“今天北京多云，23°C，湿度45%” |
| 查询上月销售额 | 回复“抱歉，我无法访问你的数据库”       | 实际连接数据库查询，提取数据并展示                  |
| 预订高铁票     | 回复“你可以去12306网站订票”            | 实际打开12306平台，完成查票、选座、下单操作         |

核心区别在于：聊天机器人仅提供语言回复，智能体真正执行操作。

## 二、智能体与 Skills 的工作机制

### 2.1 智能体的运行流程

一个完整的智能体系统包含多个组成部分，其运行遵循三个步骤：第一步，理解用户需求（依赖大模型能力）；第二步，判断应该使用哪项技能来执行任务（依赖大模型能力）；第三步，调用技能执行任务并返回结果（依赖 Skills 能力）。

### 2.2 生活中常见的智能体应用

许多现有产品已经采用了智能体技术：Siri、小爱同学、天猫精灵等语音助手，当用户说“定个闹钟”时，它们会实际设置闹钟，而不是仅仅告知用户可以自己设置；GitHub Copilot 不仅提供编程对话，还能实际编写和修改代码；各类 AI 客服系统不仅能回答问题，还能执行订单查询、退款处理、地址修改等操作；自动驾驶系统也是一种智能体，它能够感知环境、做出决策并执行驾驶操作。

### 2.3 Skills 在智能体中的定位

在智能体架构中，大模型扮演“大脑”的角色，负责理解需求、做出决策和生成语言；Skills 则扮演“手和脚”的角色，负责实际执行任务。没有 Skills 的智能体，就像一个只有大脑而没有手脚的人——虽然具备认知能力，但无法完成任何实际操作行为。

Skills 本质上是一份操作说明书：智能体本身具备智能，但需要有人告诉它在特定的环境条件下、完成某项具体任务时，应该使用哪些工具、遵循哪些步骤、注意哪些常见问题。这份说明书就是 Skill。

## 三、Skills 的技术实现

### 3.1 生活化比喻理解 Skills

将智能体比作一位能力很强但刚入职的新员工，他对工作内容不熟悉，不了解公司的各项流程。Skill 就相当于公司的标准操作流程手册。有了这本手册，新员工就知道遇到客户投诉时的处理流程、出差报销的操作步骤、代码提交需要经过哪些审核环节等，无需每次都向他人询问，能够自主完成任务。

### 3.2 Skills 的技术格式

从技术角度看，Skill 是一个 Markdown 格式的文件，文件名为 SKILL.md，其中记录了完成某项任务的完整操作指南。这个文件由人类编写，智能体在执行相关任务时会自动读取并遵循其中的指引。

## 四、Skills 解决的问题

### 4.1 没有 Skills 的场景

以请求 Claude 生成一份 Word 文档为例：用户说“帮我生成一个项目计划书的 Word 文档”，Claude 会回复一份项目计划书的内容，但输出的是 Markdown 格式的纯文本，并不是真正的 .docx 文件。原因在于 Claude 不知道用户环境中安装了哪些库、文件应该保存到什么位置、文档格式有哪些具体要求。

### 4.2 配备 Skills 之后的场景

当系统配置了 docx Skill 之后，Claude 收到同样的请求时，会自动识别出“这是一个 Word 文档任务”，从而触发 docx Skill。然后它会读取 Skill 文件，了解应该使用 python-docx 库、输出路径为 /mnt/user-data/outputs/，并按照 Skill 中记录的步骤生成真正的 .docx 文件，最后将文件提供给用户下载。结果完全不同：前者只是聊天回复的文字，后者是可以直接打开的 Word 文件。

## 五、Skills 的核心要点

### 5.1 三大核心价值

第一，Skills 使智能体从对话型转变为行动型。没有 Skills 时，智能体只是一个知识丰富的聊天机器人；有了 Skills 之后，它成为能够真正完成任务的执行者。

第二，Skills 是可重复使用的经验集合。一旦有人将生成 Word 文档这类任务的经验编写成 Skill，所有用户在任何时候调用，都能获得稳定一致的结果，不会因为提问者不同而失效。

第三，Skills 是人与 AI 协作的桥梁。人类将领域知识、流程经验和环境约束条件编写进 Skill；AI 读取这些内容后去执行任务。人类专注于定义“怎么做”，AI 负责“实际去做”。

### 5.2 概念速查表

| 概念          | 一句话定义                                                   |
| ------------- | ------------------------------------------------------------ |
| AI 智能体     | 能够感知、推理和执行任务的 AI 系统，不仅限于对话功能         |
| Skills        | 告诉智能体“如何完成某类任务”的操作说明书（Markdown 文件格式） |
| Skills 的价值 | 确保任务执行的准确性、稳定性和可复用性                       |

## 六、Skills 与 MCP 的对比

### 6.1 定位差异

Skills 用于知识复用，MCP 用于能力扩展。

Skills 的特性：
- 用途：知识分享，包括经验、最佳实践和工作流程
- 创建方式：基于简单的 Markdown 文件，任何人都可以创建
- 加载机制：渐进式加载，Token 使用效率较高
- 基础设施：无需服务器或后端配置
- 适用环境：Web 端、桌面端、命令行界面均可使用

MCP 的特性：
- 用途：功能扩展，包括连接 API、数据库和外部工具
- 创建方式：需要编程能力和服务器端配置
- 加载机制：启动时加载全部工具定义
- 基础设施：对外部系统的集成能力较强
- 限制：Token 消耗较高，复杂度也更高

## 七、Skills 的应用场景与工具支持

### 7.1 适用场景

Agent Skills 适用于多种场景，主要包括：

- 领域专业知识：将法律审查、数据分析、代码规范等专业领域的知识封装成技能
- 工作流程：将多步骤的任务流程固化为可重复使用的技能
- 公司规范：将公司特定的代码规范、代码提交流程、文档模板等封装成技能
- 工具集成：封装特定工具的使用方法和 API 调用方式

### 7.2 支持的工具

Agent Skills 采用开放标准，被多种 AI 工具所支持，包括 Claude Code、OpenCode、GitHub Copilot、OpenAI Codex 以及其他众多 AI 代理工具。这意味着只需要编写一次技能，就可以在不同的工具中使用。
