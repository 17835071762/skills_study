# Skills 工作原理详解

## 核心概念：Skill 是什么？

Skill 是 Claude Code 的能力扩展模块。每个 Skill 背后都有一个描述文件（通常叫 `SKILL.md`），相当于一份**说明书**，告诉 AI 这个 Skill 能做什么、该怎么做。

**简单理解**：Skill 就像给 AI 安装的一个"插件"或"技能包"。

## 工作原理：渐进式披露

Skills 使用**渐进式披露（Progressive Disclosure）**的方式，让 AI 在不同阶段加载不同详细程度的信息。这种设计使得 AI 可以同时管理大量技能，而不会耗尽上下文空间（即 AI 的"短期记忆"限制）。

### 三个阶段对比

| 阶段         | 加载内容           | 大小              | 作用             |
| ------------ | ------------------ | ----------------- | ---------------- |
| **发现阶段** | name + description | 约 100 tokens     | 判断技能是否相关 |
| **激活阶段** | 完整 SKILL.md      | 建议 ≤5000 tokens | 读取完整指令     |
| **执行阶段** | 脚本、参考资料     | 按需加载          | 实际执行任务     |

### 各阶段详解

**① 发现阶段**

当对话开始时，AI 会扫描所有可用的技能文件夹，但**只读取**每个技能的：
- 名称（name）
- 描述（description）

这是最轻量的信息，足以让 AI 判断某个技能是否与当前任务相关。

**② 激活阶段**

当 AI 判断某个技能的描述与用户请求相匹配时，会将**完整的 SKILL.md 文件内容**加载到上下文中。这时 AI 会读取：
- 完整的指令
- 详细说明
- 使用规则

**③ 执行阶段**

AI 按照 SKILL.md 中的指令执行任务。在这个过程中，AI 可能会：
- 调用技能附带的脚本
- 读取参考资料
- 使用其他资源

## AI 如何"读懂"一个 Skill？

AI 在执行任务之前，会先读这份说明书，搞清楚三件事：

| 问题                       | 说明               |
| -------------------------- | ------------------ |
| **这个 Skill 能干什么？**  | 能力描述           |
| **要用它，需要提供什么？** | 输入参数           |
| **做这件事有什么规矩？**   | 环境约束和注意事项 |

读完之后，AI 就知道：这个 Skill 适合用来解决当前的问题，然后调用它。

## 打个比方

想象你新入职一家公司，拿到一本《岗位操作手册》：

| 手册内容                   | 对应 Skill |
| -------------------------- | ---------- |
| "你是客服，负责处理退款"   | 能力描述   |
| "先核实订单号，再提交退款" | 操作流程   |
| "超过500元需主管审批"      | 注意事项   |

读完手册，你就知道自己该干什么、怎么干、什么不能干了。**SKILL.md 对 AI 来说，就是这本"操作手册"。**

## Skill 执行流程

从用户指令开始，整个流程如下：

```
用户提出需求
    ↓
AI 理解任务内容
    ↓
分析应该使用哪些能力（Skills）
    ↓
命中 Skill → 加载 SKILL.md
    ↓
建立工具权限与行为边界
    ↓
结合上下文进行推理
    ↓
在规则内完成逻辑
    ↓
必要时调用被允许的外部工具
    ↓
结果整合后输出
    ↓
用户的下一次输入触发新一轮流程
```

## 完整闭环：理解 → 决策 → 执行 → 返回结果

| 步骤 | 阶段         | AI 内部动作                | 示例                               |
| ---- | ------------ | -------------------------- | ---------------------------------- |
| ①    | 用户发起请求 | 接收自然语言任务           | "帮我查询北京今天的天气"           |
| ②    | 理解用户意图 | 分析真正想做什么，提取参数 | 动作：查询；类型：天气；地点：北京 |
| ③    | 制定执行计划 | 拆分任务步骤               | 找天气服务 → 获取数据 → 整理结果   |
| ④    | 选择 Skill   | 匹配最适合的能力模块       | 选择 Weather Skill                 |
| ⑤    | 执行 Skill   | 调用外部工具或 API         | 请求天气接口                       |
| ⑥    | 获取执行结果 | 接收 Skill 返回的数据      | 温度、湿度、空气质量               |
| ⑦    | 生成最终回复 | 整理并转换为自然语言       | "北京今天晴，18℃~30℃"              |
| ⑧    | 返回给用户   | 输出最终结果               | 用户看到完整回复                   |

## Skill 类型一览

| Skill 类型     | 功能说明       | 常见场景           |
| -------------- | -------------- | ------------------ |
| 搜索 Skill     | 查询外部信息   | 搜索新闻、知识问答 |
| 天气 Skill     | 获取天气数据   | 天气查询           |
| 文件 Skill     | 读取文件内容   | PDF、Word、Excel   |
| 数据分析 Skill | 数据计算和统计 | 报表分析           |
| 数据库 Skill   | 查询数据库     | MySQL、PostgreSQL  |
| 浏览器 Skill   | 自动操作网页   | 自动登录、爬取内容 |
| 代码 Skill     | 执行代码       | Python、Node.js    |
| 图像 Skill     | 图像处理能力   | OCR、图片生成      |

## 核心要点总结

1. **渐进式披露**：分阶段加载信息，节省上下文空间
2. **说明书驱动**：每个 Skill 都有 `SKILL.md` 作为操作手册
3. **AI 负责思考决策**，Skill 负责执行动作
4. **形成闭环**：理解 → 决策 → 执行 → 返回结果
5. **可扩展**：可以创建各种类型的 Skill 来扩展 AI 能力
